# CooldownCollaborator — CLAUDE.md

Group & raid cooldown coordinator for **WoW Midnight (12.x)**. Author: Nelnamara.
Tracks party/raid members' major defensive & utility cooldowns, an Essentials bar
(Bloodlust/Battle-Rez "ready" providers + Rez request), a Lane view, group
flask/food status, and a minimap button.

## Files
- `CooldownCollaborator.lua` — core: client detection and `CC.Compat` (top), init, DB defaults, event frame, `RecordCooldown`, `RecordCooldownFromComm` (one record per cast: a second report within 5 s is the same cast), own-spell readiness (`GetLocalReadiness`, `KnownRank`, ready-now poll), Rez logic, slash `/cdc`.
- `Data.lua` — shared: `CC.ClassColors`, and `CC:BuildSpellIndex()` (run in Init) → `CC.RankToBase[anyRankID] = baseID` and `CC.SpellByName` (English and client names); `CC:BaseSpellID(id)`.
- `Data_Retail.lua`, `Data_Mists.lua`, `Data_TBC.lua`, `Data_Era.lua`, `Data_Forever.lua` — one per client, each TOC loads only its own: `CC.SpellData[baseID] = { name, duration, icon, class, ranks = {...}, level }` (ranks on Era/TBC/Forever; every rank records under, and is sent as, the base ID; `level` on provider spells only = rank 1's `BaseLevel` in that client's SpellLevels table), `CC.Providers` (lust / Battle Rez classes → base IDs), `CC.BuiltinConsumables` (with `category`) and `CC.ConsumableMatch` ("id" Retail/Forever, "name" Era/TBC/MoP). Rows are checked against the game data (SpellName, SpellCooldowns, SpellMisc icons, SpellDuration) of the builds in `cdtl3-dev/tools/spell-list-check/builds.json`; `docs/port-research.md` section B has the tables. Soulstone is a Battle Rez provider on Retail and MoP (it can be cast on a dead player; on Retail it uses a combat rez charge; owner 19 Nov 2026) and tracked only on Era, TBC and Forever (a stone placed beforehand), where its cooldown is the item's (`itemCooldown = true`: no ready-now watch).
- `Bridge.lua` — optional CDTL3 timer-type bridge (`cdcGroup`); every call guarded, no-op without CDTL3. On Era/TBC/MoP CDTL3's own combat-log raid cooldowns step aside while this type is on (CDTL3 Group.lua `CollaboratorFeeds`).
- `Comms.lua` — addon messaging, message format 2 (`docs/MESSAGE_FORMAT_2.md`). Prefixes: `CDCOLLAB` (cooldown sync) and `CDCBUFF` (flask/food status). Casts still go out as the 1.x line `spellID:secondsAgo:name:class` and ready-nows as `R:spellID`; new kinds `H` hello (version, client), `Q` state request, `S` own running cooldowns (absence = ready), `C` battle rez charges (`CC.rezCharges`; `CC:RezPool()`; an empty known pool gives Battle Rez entries `noCharges` and makes Request Rez say "No Battle Rez charges; next in M:SS"), `T` a Soulstone the warlock placed on a living group member (Retail and Forever; Era, TBC and MoP read it from the combat log; `CC.stones[target]`), `P`/`O` chunked payloads (only stored, in `CC.payloads`). Joining, login or /reload in a group sends H, Q, our S and CDCBUFF; a Q is answered with H, S and CDCBUFF after 0 to 3 s, once per 10 s. One send queue for both prefixes (`CC:QueueSend`): one message per 0.25 s per channel, the same text within 1 s dropped, a refused send retried every 2 s up to 15 times; refused ready-nows from a boss go out once at its end. Heard only from `PARTY`/`RAID`/`INSTANCE_CHAT` and current members (whispers dropped; `GUILD` only for `O`, and with guild sharing on (`db.guildSync`, P41) H, Q and S into `CC.guildPeers` / `CC.guildState`, never the group's tables); a message belongs to its sender (an old copy's relay naming someone else is dropped); secondsAgo outside 0 .. duration is dropped. `CC.peers[name]` = { version, client, proto } (proto 1 = an old 1.x copy; boss ends also send the 1.x lines unless every other member has said a format 2 hello). `CC:GroupChannel()` (INSTANCE_CHAT in an instance group, else RAID/PARTY); `CC:AddonMessageSent(result)` (nil, true, 0, `Enum.SendAddonMessageResult.Success` = sent; anything else is retried).
- `Events.lua` — `UNIT_SPELLCAST_SUCCEEDED` ("player" only) and, on Era/TBC/MoP, the combat-log path: `COMBAT_LOG_EVENT_UNFILTERED` registered only where `retailAPI` is false and the accessor exists, in a pcall; `SPELL_CAST_SUCCESS` from party/raid players (not me, no pets) → `CC:MatchSpell` (ID, any rank, then name) → `RecordCooldownFromComm` with the class from `GetPlayerInfoByGUID` (pcall). Nothing is sent for those casts. Also roster pruning and `BroadcastState`.
- `Roster.lua` — capability table built from `CC.Providers` (no provider on this client → no capability, lane, header or Essentials slot: no lust on Era/Forever); `NotifyInspect` spec labels on Retail only. Who provides (1.1.1): `CC:CapabilitiesFor(unit, class)` keeps a class's provider spells whose `level` the unit has reached (`UnitLevel`; 0, -1 or a hidden value counts as reached), redone per member on `UNIT_LEVEL` (`CC:OnUnitLevel`, no rescan so Retail's inspect queue isn't restarted). For ourselves `GetCapabilityStatus` also needs `CC:KnownRank` (the spellbook), so a spell not bought from the trainer yet doesn't list us. Others are never asked over the wire whether they know it: the owner's ruling, players at the level have it.
- `Essentials.lua` — the Essentials bar (ready providers + flask/food strip), and `CC:StylePanelFrame(f, r, g, b)`, the panel look (strata, drag, clamp, backdrop) the Lane view shares.
- `Lanes.lua` — Lane view (one lane per capability the client has). Like the Essentials bar it only opens in a group; `ScanRoster` refreshes both, so joining a group with it on opens it (1.1.1), and `/cdc lanes` turned on while solo says so.
- `Consumables.lua` — self-poll of own flask/food auras → broadcast category presence. Retail/Forever: `GetPlayerAuraBySpellID` by ID (auras secret); Era/TBC/MoP: the readable aura list, built-ins by name, `/cdc consumable` entries by spell ID.
- `UI.lua` — the main panel (19 Nov look picks): running first, ready ones folded per spell, two columns from 10 players, 28 lines then "+N more", no flask or food; greyed DEAD / OFFLINE, `?` on guessed ready lines, version dots and "N of M" in the title, the next lust in the title, rotation numbers (`CC.rotations`, shared as `P:2:rot-<id>`), team tabs (`db.teams`), a Guild tab, the icon style (`db.panelStyle = "icons"`), the effect bar (`effect` on the data rows), click to ask (whisper; Shift: group). Its close button keeps it shut until /cdc or the minimap (`db.panelClosed`, `CC:TogglePanel`).
- `Tooltip.lua` — `CC:ShowCooldownTooltip(anchor, owner, spellID)` / `CC:HideCooldownTooltip()`: the game's spell tooltip, then when it matters (from the row's `kind`), the owner and time left, guessed and old-copy notes.
- `Alerts.lua` — `db.alerts[spellID]`: `CC:FireReadyAlert(owner, spellID)` once per ready (sound, row and Essentials flash, optional mid-screen icon, optional warning N s before).
- `DeadList.lua` — the dead list window: the dead in the leader's order (healers, tanks, damage) with a Call button each and who would answer; goes through `CC:RequestRez`; opens when someone dies in combat; `/cdc rez` with nobody targeted calls the top.
- `Strips.lua` — the externals strip (kind "external") and the mana strip (kind "mana", with an Ask button anyone may press); a `?` on unconfirmed ones, dead or offline owners greyed.
- `Burst.lua` — the burst line: your own big cooldowns above a 2-minute line, the group's lust and Power Infusion below, a gold band where they meet (`db.burstSpells`).
- `Plan.lua` — the raid plan runtime: plans (`db.plans`, shared by the leader or an assist as the format 2 `P` kind), prompt bars from BigWigs or DBM timers or a time into the fight, late planned spells for the panel, and the pull countdowns the Lane view's next hit uses.
- `Setups.lua` — window places and the joined block (`CC.BLOCK_KEYS`: Essentials bar, main panel, Lane view start joined top to bottom from `blockX`/`blockY`, each hanging from the shown one above; drag the top to move all, drag another to pull it loose, drop within 12 px of the block to rejoin; `LayoutBlock`, `StartWindowDrag`/`StopWindowDrag`, `SettleWindows`, `RejoinWindow`; a slot per window in places, layouts, profiles and setup text; an old save joins only windows still at the old defaults), profiles like AceDBOptions (Default always there; `CC.PROFILE_KEYS` are per character, the rest account-wide), setups as text, officer setups over the guild channel (`O` kind; Accept, Not now, Never), party and raid layouts, the last pull log, `/cdc post`, the key-start reset, `/cdc report` (`CC:ShowReport`), and the public feed `CC.API` (`docs/API.md`).
- `Tour.lua` — sample windows and the first-run tour. `CC:ShowSample(key)` / `CC:HideSample()`: a window shows itself with made-up players and this client's real spells for 20 seconds, even solo, drawn by its own refresh (for that call `CC.state`, `CC.roster`, `CC.peers`, the rez charges and the group's names are the sample's, `CC.sampling` is true, and the windows' solo and "on" gates let it through); a real group event (a cast heard, a roster change in a group, combat) or closing Settings ends it, and Call, Rez, Ask and a click on a sample say it is a sample and send nothing. The tour (`CC:StartTour`, `/cdc tour`, Take the tour): all seven windows in `CC.WINDOWS` order (an off one as its sample, with a line saying where to switch it on; nothing is switched), a gold edge and a bubble with the window's one line (`CC.WINDOW_HELP`, Options.lua); the last step has Lock in place and Open settings; starts by itself once per account (`db.tourDone`, not in a profile) in a group with a window showing; a combat start ends it.
- `Options.lua` — the standalone settings window, six tabs: Getting Started (pick a window from the list: its line, notes on its parts, Lock, Reset, Show it now), Display, Bars & Lists, Spells (Your role cards over `CC.PRESETS`, folded Kinds of spells, Default and Custom Spells), Plans (raid plan, rotation order, teams), Profiles. `Minimap.lua`.
- `docs/API.md` — the public feed other addons read (`CooldownCollaboratorAPI`). `docs/MESSAGE_FORMAT_2.md` — the group sync format as built.
- `Locales/` — translations. `Locales.lua` makes `CC.L` (a missing phrase returns itself: the English text is the key) and `CC.NewLocale(name)`; `enUS.lua` lists every phrase as `L["text"] = true` (rebuild with `python tools/gen-enus.py`) and one stub per other language holds the CurseForge packager line. Every player-visible string goes through `L[...]`; names and spell names are data inserted with `string.format` into a translated pattern. Slash words, saved keys, the wire format and debug output (`-- debug`, or between `debug begin` / `debug end`) stay English. `tools/tests/locale.lua` (plain and `pseudo`) checks it.
- `tools/tests/` (not packaged) — the test suite, see Build.

## Midnight API gotchas (critical)
- `aura.spellId` / `aura.name` are **SECRET** even on `"player"`. Only safe lookup is `C_UnitAuras.GetPlayerAuraBySpellID(knownID)`. This is why flask/food tracking is peer-broadcast (each client detects its own, announces via `CDCBUFF`).
- `UNIT_SPELLCAST_SUCCEEDED.spellID` is **SECRET** for party/raid tokens — only `"player"` is safe. Other players' cooldowns arrive only via the `CDCOLLAB` addon message.
- `GetTime()` is per-client (seconds since that client's process start). Wire **secondsAgo**, not a raw timestamp; receiver re-anchors with `GetTime() - secondsAgo`.
- `RegisterUnitEvent` **overwrites** the unit filter (doesn't accumulate) — use `RegisterEvent` + manual token filtering.
- `AreOutgoingAddonChatMessagesRestricted()` is unreliable — attempt the send and queue/retry on a non-nil result code.
- **12.0.7 un-secreted combat-res (and some whitelisted) cooldowns + charge counts for the `"player"`.** `CC:GetLocalReadiness(spellID)` (in `CooldownCollaborator.lua`) reads your OWN Battle-Rez/Bloodlust true cooldown + the raid Battle-Rez charge pool via `C_Spell.GetSpellCooldown`/`GetSpellCharges`, pcall-guarded; `Roster.lua:GetCapabilityStatus` prefers it for the local player and falls back to the observed-cast model when unreadable. Remote players' values stay secret → still comm-only. (v1.0.3)

## Combat rez rule (owner, 19 Nov 2026)
"A soul stone and raise ally still count as a combat rez." Providers: Retail Rebirth, Raise Ally, Intercession, Soulstone (`CC.Providers.BATTLEREZ`: druid, death knight, paladin, warlock); MoP Rebirth, Raise Ally, Soulstone; Era, TBC and Forever Rebirth only, with Soulstone tracked (a stone placed beforehand). On Retail every combat rez draws from one shared charge pool; at zero nobody can be rezzed, a placed Soulstone included, so the Essentials bar and Request Rez say "no charges, next in M:SS" instead of naming a rezzer. The warlock's client shares who it stoned (`T` kind) because other players' buffs are hidden in combat on Retail.

## Build / release / deploy
- BigWigs **packager runs on `v*` tag push** (GitHub Actions). Pushing `main` does NOT release.
- CurseForge API secret is named **`CURSFORGE_API_KEY`** (misspelled — missing the E — but consistent across the suite; do not "fix" it).
- **One package, six TOCs** (copied from CooldownTimeline3): `_Mainline` (120105 Retail), `_Mists` (50504 MoP Classic), `_TBC` (20506 TBC Anniversary), `_Vanilla` (11509 Classic Era), `_Camelot` (16001 WoW: Forever) and an unsuffixed `CooldownCollaborator.toc` (16001, the Forever fallback: Forever loads `_Camelot` then the plain TOC, never `_Mainline`). One Interface number per TOC (the packager fails a suffixed TOC carrying another game type's number); all six must keep the same `## SavedVariables: CooldownCollaboratorDB` and `## Version`; `X-Curse-Project-ID: 1577127` sits in the unsuffixed, `_Camelot` and `_Mainline` TOCs. File lists are identical except the one `Data_<client>.lua`. Bump each TOC's Interface when its client patches. `.pkgmeta` keeps `CLAUDE.md`, `README.md`, `docs`, `tools` and the `Media/*.png` source art out of the package.
- **Client detection** (`CooldownCollaborator.lua` top, same rules as CDTL3.lua): `CC.tocversion` picks content (the TOCs pick the spell list); `CC.retailAPI = tocversion >= 110000 or CC.isForever` picks which API calls exist; `CC.isForever` = the 16000–16999 band (Forever is the modern engine with a vanilla interface number: secret values, no combat log, no `IsSpellKnown`/`GetSpellInfo` globals); `CC.isRetail` gates specs/inspect. Never pick an API by interface number alone; call `CC.Compat.IsSpellKnown` / `CC.Compat.GetSpellInfo`, not the bare globals. Own cooldowns: `C_Spell` (isActive) where `retailAPI`, legacy `GetSpellCooldown`/`GetSpellCharges` elsewhere (no isActive there). Hidden values are only compared inside a pcall.
- **Tests**: `powershell -File tools\tests\runall.ps1` (on the Mac: `sh tools/tests/runall.sh`, the same list; keep the two in step) loads every TOC (all six) under its client's stubbed API and runs nine harness passes in `tools/tests/`: `checks.lua` (tracked rows, providers, rez rules), `groups.lua` (a /reload in a big raid, "+N more", leaving the group), `sync.lua` (two or three copies, each in its own stubbed client and clock, on a fake group channel carrying the real messages: format 2, old 1.x lines, saved timers, the guild channel), `looks.lua` (the Lane view's rows and rings, next hit, dead list, strips, burst line, plan prompts at 5, 20 and 40 players), `essentials.lua` (every Essentials bar look at 5, 20 and 40), `panel.lua` (the main panel at 5, 20 and 40 players, marks, tabs, tooltip, alerts, click to ask), `settings.lua` (windows, presets, alerts, rezzers to skip, combat or boss windows, lighter mode, profiles), and `locale.lua` twice (plain and `pseudo`). (fengari; `run.js` is cdtl3-dev's runner and loads fengari from the sibling `cdtl3-dev/tools/spell-list-check/node_modules`, so `npm install` there first, or set `FENGARI_DIR`.) It prints one `RESULT ...: ... fails 0, lua errors 0` line per harness pass per TOC (9 x 6 = 54 in all), plus any `FAIL` line; a harness that dies before its RESULT prints `NO RESULT` and counts as a failure. The stub's `Advance(dt)` runs each timer at its own time. `wow.lua` is cdtl3-dev's stub client cut down, with each client's real gaps. One TOC by hand: `node tools\tests\run.js . 11509 tools\tests\checks.lua CooldownCollaborator_Vanilla.toc`. Keep tests in the repo.
- **WoW API code check** (what addon reviewers run): `python ../cdtl3-dev/tools/luals-check/run.py .` (setup and known noise in that folder's README). 17 Nov 2026 it found Request Rez calling `IsRaidLeader` / `IsRaidOfficer`, which no client has; the stub client must never define a function the real clients lack, or the suite hides it. **The bar is 0 warnings** (since 17 Nov 2026): a line that is right on purpose (a Classic-only call in its branch, a Compat shim) carries its reason in a comment and `---@diagnostic disable-next-line: <code>` directly above it, never a file-wide disable.
